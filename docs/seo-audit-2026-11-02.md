# Kontrola SEO Wroomer.pl — 2026-11-02

## Zweryfikowane w kodzie
- `vercel.json`: /auto/:slug kieruje do /api/seo-auto?slug=:slug.
- `api/seo-auto.js`: waliduje slug, pobiera ogłoszenie z Supabase, zwraca 404 dla brakującego ogłoszenia, ustawia canonical, meta description, Open Graph i schema.org Car.
- `api/sitemap.js`: pobiera publiczne ogłoszenia, waliduje identyfikator URL, tworzy URL-e ogłoszeń i wybranych kategorii.
- `index.html`: ma canonical, meta description, robots i dane strukturalne.
- Wyszukiwanie literalnego `${slug}` w indeksie kodu GitHub nie zwróciło wyników; to NIE dowodzi braku problemu.

## Do sprawdzenia przed zmianami produkcyjnymi
1. Zlokalizować wszystkie miejsca generujące odnośniki do /auto/ (także skrypty, szablony i artykuły).
2. Sprawdzić HTTP status, canonical, robots i treść HTML dla przykładowych aktywnych, usuniętych i zbanowanych ogłoszeń.
3. Porównać /sitemap.xml i /sitemap-ogloszenia.xml z rzeczywistymi stronami i sprawdzić odnośniki z robots.txt.
4. Sprawdzić, czy strona z błędnym `/auto/${slug}` zwraca 404, nie 200.
5. Sprawdzić reguły RLS i ekspozycję danych Supabase, a także indeksowanie stron testowych.
6. Zmiany wdrażać przez osobny PR po testach, bez modyfikacji main na etapie diagnozy.

## Ryzyka
- Nie należy masowo przekierowywać nieznanych adresów na stronę główną (soft 404).
- Nie należy automatycznie indeksować wszystkich kombinacji filtrów, które nie mają wartościowej treści.
- Nie należy usuwać istniejących adresów ogłoszeń bez mapy przekierowań.
