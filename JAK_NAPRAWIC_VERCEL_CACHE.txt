Vercel - plik się nie wgrywa, część zostaje stara - ROZWIĄZANIE

PROBLEM: Vercel cache - serwuje starą wersję mimo nowego commita

ROZWIĄZANIE KROK PO KROKU:

1. Sprawdź GitHub:
   - Wejdź na github.com/twoje-repo
   - Czy widzisz 5 plików: index.html, admin.html, rollback.html, vercel.json, package.json ?
   - Czy ostatni commit ma dzisiejszą datę i wersję 34?
   - Jeśli nie - nie wgrałeś wszystkiego, wgraj ZIP ponownie, zaznacz WSZYSTKIE pliki, Commit

2. Sprawdź Vercel Deployments:
   - vercel.com -> Twój projekt -> Deployments
   - Czy ostatni deployment ma status Ready i dzisiejszą datę?
   - Kliknij ostatni deployment -> View Build Logs - czy są błędy?
   - Jeśli nie ma nowego deploymentu - GitHub nie połączył się z Vercel, kliknij Redeploy

3. Wymuś czyszczenie cache:
   - Vercel -> Deployments -> ... (3 kropki) -> Redeploy -> ODZNACZ "Use existing Build Cache" -> Redeploy
   - To wymusza budowanie od zera bez cache

4. Twardy refresh przeglądarki:
   - Na portalu naciśnij Ctrl+Shift+R (Windows) lub Cmd+Shift+R (Mac)
   - Lub Ctrl+F5
   - Lub otwórz w trybie incognito

5. Sprawdź wersję w kodzie:
   - Otwórz źródło strony Ctrl+U, szukaj "version" - powinno być "34-sidebar-no-cache-2026-05-13-2200"
   - Jeśli jest stara wersja 32 lub 33 - Vercel nadal serwuje stary plik

6. Ten ZIP ma no-cache headers w vercel.json:
   - Cache-Control: no-cache, no-store, must-revalidate
   - Vercel nie będzie cache'ował

7. Jeśli nadal nie działa - usuń projekt Vercel i stwórz nowy:
   - Vercel -> Settings -> Delete Project
   - Import ponownie z GitHub

TEN PLIK MA CACHE-BUSTING - WGRAJ GO I KLIKNIJ REDEPLOY BEZ CACHE
